# Ed25519 理解メモ

自作しながら「Ed25519 とは何か」を理解するためのメモ。まず「何ができるのか」から。
中身の数学（有限体・曲線・署名式）は実装を進めながら下に書き足していく。

## 1. Ed25519 は何ができるのか

Ed25519 は **デジタル署名** の方式。**暗号化（中身を隠す）ではない。**
やることは「この文書は確かに秘密鍵の持ち主が作った／改ざんされていない」を証明すること。

署名が保証する3つ:
- **真正性 (authenticity)** … 送り主が本人だと分かる
- **完全性 (integrity)** … 1bit でも変わったら検知できる
- **否認防止 (non-repudiation)** … 後から「送ってない」と言えない

保証しないもの:
- **機密性 (confidentiality)** … メッセージ本文は隠れない。署名しても誰でも読める

## 2. 「暗号化」がしたいなら別物

- 中身を隠す（秘匿）= AES / ChaCha20（共通鍵暗号）
- 鍵を安全に共有する = **X25519**（ECDH 鍵交換）
- X25519 と Ed25519 は同じ Curve25519 系で名前が似ているが **用途が別**
  （X25519 = 鍵共有、Ed25519 = 署名）

## 3. どこで使われているか

- SSH の鍵
- TLS 証明書
- **Git のコミット署名**
- ソフトウェア更新の署名（正規の配布元か確認）
- JWT、暗号通貨のトランザクション署名

いずれも「本人性」と「改ざん検知」が欲しい場面。

## 4. コアの操作は3つだけ

Ed25519 の機能は小さい。コアはこの3つ:

- `generateKey` … seed から鍵ペア（秘密鍵 / 公開鍵）を作る
- `sign` … 秘密鍵でメッセージに署名する（64byte の署名）
- `verify` … 公開鍵で署名が正しいか検証する（true / false）

**この3つを自作できたら Ed25519 は「完成」。**
→ 当面のゴール `TestAgainstStdEd25519`（標準 crypto/ed25519 と一致するか）が
  まさにこの3つを確認している。

## 5. 応用（余裕があれば）

コアではないオプション。やらなくても Ed25519 として成立する:

- **Ed25519ph** … 先にメッセージを SHA-512 でハッシュしてから署名（大きなファイル向け）
- **Ed25519ctx** … コンテキスト文字列付き（用途の分離）
- **バッチ検証** … 多数の署名をまとめて速く検証
